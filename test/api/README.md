# Worker API checks

This directory exercises `POST /v1/render` against the local render Worker. It makes no network calls beyond loopback and uses the shared browser-WASM fixtures. `output/api-tests/` contains generated large inputs, response PNGs, Wrangler persistence, and JUnit reports; it is gitignored.

## Requirements

- Node and pnpm versions supported by the repository.
- Hurl installed and available as `hurl` on `PATH`.
- Yaak installed for manual inspection. The checked-in collection uses the documented Postman v2.1 import format because the Yaak native export format is generated by the desktop app.

## Run the checks

```sh
pnpm test:api:smoke
pnpm test:api
pnpm test:api:limits
pnpm api:serve
```

`test:api:smoke` starts local workerd, renders the poster and QR fixtures, and checks the transparent and rotated poster outputs. `test:api` adds routing, authentication, and recipe validation cases. It runs three sequential Hurl groups with a full quota-window wait between groups, so it takes a little over two minutes on an already warm machine. `test:api:limits` checks oversized requests and image declarations, then waits for an idle window before the isolated eleven-request rate-limit case. The rate-limit group makes no render calls.

`api:serve` starts the same isolated local Worker and prints the loopback URL and a fresh bearer token for Yaak; press Ctrl+C to stop it. It creates the generated limit fixtures first, so the Limits folder can use the same paths as Hurl.

The runner resolves Wrangler from `apps/render-api/` and derives a test-only config under ignored `output/api-tests/`, so local development does not load `apps/render-api/.dev.vars` or the repository `.env`. It binds only `127.0.0.1:8799`, supplies a freshly generated test token through a mode-0600 environment file in that ignored directory, uses persistence under `output/api-tests/`, gives Hurl requests 5-second connect and 60-second total timeouts, and removes the token file when it stops the Worker. It never deploys. Hurl writes JUnit reports and successful PNG responses under `output/api-tests/`.

The fixture generator `pnpm api:fixtures` assembles the expected images through the browser WASM backend in Node, then saves the independently generated recipe, poster, QR, and SHA-256 manifest. It also creates malformed inputs and large request-limit payloads. Regenerate fixtures after an intentional rendering change and review the decoded pixels and recipe before accepting new hashes.

## Use Yaak

Import [the Postman v2.1 collection](yaak/mahu-qr-worker-api.postman_collection.json) using Yaak's Import Data flow and choose a new workspace. Run `pnpm api:serve`, then set `render_api_token` in that workspace's local environment to the printed token; keep the collection's shared default URL at `http://127.0.0.1:8799` while the local worker is running.

For a render request, choose **Body → Binary File** and select the matching recipe under `test/api/fixtures/`. The file path in an imported collection is a portability hint; reselect the file if Yaak does not resolve it from the repository root. Keep calls sequential. Yaak's Send All can issue folder requests concurrently, and each authenticated attempt, including a validation error, consumes one rate-limit slot.

The checked-in Postman collection can be re-imported as a starting point. If a native Yaak workspace export is desired, export it from Yaak after configuring local paths; do not commit secure variable values or response history.

## Case coverage

| Hurl file              | Cases                                                                                                                                                                                                                                                                                                             |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hurl/smoke.hurl`      | Default/explicit poster, standalone QR, transparent and rotated poster; status, media type, cache/security headers, attachment filename, request ID, response PNG SHA-256                                                                                                                                         |
| `hurl/contract.hurl`   | GET/PUT/OPTIONS method rejection, unknown path, missing/wrong authentication, media type, artifact, malformed JSON/UTF-8, image digest, placement, and charset-bearing JSON; health liveness (`GET`/`POST`/`HEAD`), `HEAD` render rejection, trailing-slash 404s, and method-guard-before-authentication priority |
| `hurl/recipes.hurl`    | Unsupported recipe and renderer versions, missing/unknown fields, invalid content/base64/dimensions/PNG, invalid placement and palette                                                                                                                                                                            |
| `hurl/limits.hurl`     | 28 MiB request ceiling, oversized embedded base64 image, and invalid declared source dimensions                                                                                                                                                                                                                   |
| `hurl/rate-limit.hurl` | Ten authenticated validation attempts followed by the expected 429 response                                                                                                                                                                                                                                       |

Error bodies use a JSON `requestId`; successful PNGs use the `X-Request-Id` response header. The tests assert those different current contracts. The Worker entry is a Hono app whose known paths carry explicit method guards ahead of authentication (Hono matches `HEAD` with the `GET` route, so the guards check the original request method), and the rate limiter runs after authentication but before content type and recipe validation. Hono strips response bodies for `HEAD` requests, so the `HEAD` cases assert status and headers only.

Some current error mappings follow the existing handler rather than normalizing every limit failure: an excessive declared pixel count can produce 413 `IMAGE_TOO_LARGE`, while certain PNG header or dimension failures produce 400 `PNG_INVALID` or 400 `RECIPE_INVALID`. Update these assertions only with an intentional API contract change.

## Known limits

- The committed `invalid-digest.recipe.json` fixture tampers the recipe content instead of an embedded image digest. The longer content re-encodes the QR at a higher version, so the renderer rejects the placement (`422 QR_LAYOUT_INVALID`) before the digest check; the matching `contract.hurl` assertion expecting `400 RECIPE_INVALID` fails against the committed renderer and fixtures today. Fix the generator to mutate embedded PNG bytes without updating the digest, then regenerate fixtures — an intentional renderer or fixture change, not an API contract change.
- The rate-limit binding must enforce its configured ten requests per minute in the local Wrangler version for `test:api:limits` to pass. Cloudflare's global per-location production quota is not proven by a local run.
- The fixture generator exercises the browser imaging backend under Node. It does not replace full supported-range Worker memory/CPU measurements or a browser editor export capture.
- The installed `yaak-app-client` could not initialize GTK in this environment, so GUI import and file-body setup remain unverified here. Import the collection through Yaak before relying on it for a manual release check.
- General `pnpm test`, `pnpm typecheck`, `pnpm build`, editor E2E, and deployment commands remain separate maintainer checks.
