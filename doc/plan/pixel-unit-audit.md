# Pixel-unit audit and selective responsive-unit plan

Status: implementation complete, 2026-09-23. Next.js dev compilation succeeded. Maintainer visual review at larger default text sizes and 200% zoom remains the final handoff gate.

## Scope and decision rule

Audit first-party runtime code in `src/`, including explicit `px` strings, numeric StyleX lengths (which become CSS pixels), inline React styles, intrinsic image/SVG dimensions, Konva coordinates, and raster-engine dimensions. `src/app/globals.css` contains no `px` declarations. The imported Pickr theme is third-party CSS and is outside this plan. Tests and the records in `doc/plan/` contain fixture dimensions or historical measurements, not live sizing rules.

Use a relative unit only when the dimension should respond to a user's preferred text size or to available space. Keep CSS pixels for hairlines, visual details, and screen-space interaction geometry where a relative unit changes the intended meaning. Keep raster pixels and QR modules exact. The modern-web-guidance `css` guide supports font-relative UI text, unitless line-height, content-driven layout, and growing hit targets; those principles still need to be applied to each call site rather than converted mechanically.

## Implementation and handoff

1. **Pending maintainer review:** inspect the desktop columns, mobile drawers, dialogs, option grids, search and hex inputs, and result actions at 320px width, with a 20px/24px browser default font, and at 200% zoom. Browser zoom and a changed default font exercise different behavior. The current session had no available browser surface, so clipping, focus, and pointer alignment have not been visually checked.
2. **Implemented:** readable UI font sizes now use `rem`; text decorations and selected control details scale with their text; icon glyphs and poster/QR raster dimensions remain fixed. The hex field uses `ch`, and the header mascot clamps to the viewport width.
3. **Implemented:** the compact-column and drawer thresholds use matching `em` breakpoints in StyleX and `matchMedia`. Mask and dialog option grids reduce columns as their containers narrow. Dialog width scales with the root font size.
4. **Implemented:** the Konva stage now fits the measured scroll-area content width instead of subtracting a fixed 32px. QR placement, mask rasterization, module pitch, and export code were not changed.
5. **Handoff gate:** manually check keyboard access, focus visibility, drawer/dialog dismissal, scrolling to export, and no clipped text or page-wide horizontal scrolling at the sizes above; intentional canvas-region scrolling is acceptable. Confirm canvas interactions still align and the exact assembled Blob remains shared by preview/download. Next.js dev server returned HTTP 200 and compiled the changed StyleX, CSS, and component code.
